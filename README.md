# G 代码分析工具 · Slicing Lab

> 把 `.gcode` 当数据分析，而不是当文件打印。
> 输入切片产物，输出**可直接用于报价与工艺决策**的耗材、时间与成本数字。

Python · 零第三方依赖 · 已通过构造样例校验

---

## 这个工具解决什么问题

切片软件会告诉你"这个模型要打 3 小时、用 30 克料"，但**不告诉你这个数字怎么来的**，也没法批量对比不同参数方案的代价。

在工艺岗上，这带来两个具体麻烦：

| 场景 | 没有工具时 | 有工具时 |
|---|---|---|
| **客户询价** | 凭经验拍一个价，报高了丢单、报低了亏 | 耗材 + 机器工时 + 人工逐项核算，报价有依据 |
| **参数调优** | 换一组参数打一遍，靠感觉说"好像快了点" | 量化对比耗时、耗材、路径有效率，改进可复现 |
| **工艺归档** | 参数散落在各个切片工程文件里 | 逐层数据导出 Excel，形成可追溯的参数对照表 |

工具把"成本"和"时间"从**经验判断**变成**可计算的数字**。

## 功能

| 指标 | 说明 |
|---|---|
| 挤出路径 / 空驶路径 | 分别统计，并给出**路径有效率**（挤出路径占比，衡量切片参数是否浪费行程） |
| 耗材消耗 | 从 E 轴累计量换算为长度 (m) 与质量 (g) |
| 打印时间 | 优先读切片软件注释（含加速度计算，更准）；无注释则按 F 值自算 |
| 成本核算 | 耗材 + 机器工时 + 人工，所有单价假设均可自定义 |
| 逐层统计 | 每层的 Z 高度、耗时、挤出量，可导出 CSV / Excel（带原生图表） |
| 温度与风扇 | 喷嘴/热床温度设定范围及变更次数、风扇 PWM |
| 元数据识别 | 自动读取机型、材料类型、层高、喷嘴直径 |

## 用你自己的模型

```bash
# 单个文件，指定材料与成本假设
python gcode_analyzer.py my_part.gcode --material PETG --price 80 --machine-rate 3 --labor 2

# 整个文件夹批量分析
python gcode_analyzer.py ./gcode/ --json batch.json

# 对比两种参数方案（这是最有价值的用法）
python gcode_analyzer.py 方案A_0.2mm.gcode --json a.json --quiet
python gcode_analyzer.py 方案B_0.3mm.gcode --json b.json --quiet
# 两个 json 直接对比耗时 / 耗材 / 成本差异
```

### 参数说明

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--material` | PLA | 从内置密度表查密度（PLA / PETG / ABS / ASA / TPU / NYLON / PC） |
| `--density` | — | 直接指定密度 g/cm³，覆盖 `--material` |
| `--diameter` | 1.75 | 耗材直径 mm |
| `--price` | 60 | 耗材单价 元/kg |
| `--machine-rate` | 2.0 | 机器工时费 元/小时（电费 + 设备折旧，按自己情况估） |
| `--labor` | 0 | 人工/后处理成本 元（拆支撑、打磨等） |
| `--json` / `--csv` / `--figure` | — | 导出完整报告 / 逐层数据 / 图表 |

## 计算原理

### 耗材重量

```
截面积 = π × (d/2)²          # d = 1.75 mm，得 2.405 mm²
体积   = 挤出长度 × 截面积    # mm³
质量   = 体积 / 1000 × 密度   # g，因为 1 cm³ = 1000 mm³
```

> **关键点**：G 代码里的 E 值是耗材**长度**，不是体积，也不是重量。
> 换算必须经过截面积这一步 —— 手算与脚本必须一致，否则说明系数写错了。

### 挤出量累计

- `M82` 绝对模式：E 值是累计总量，需用**相邻差值**
- `M83` 相对模式：E 值就是本段挤出量，直接用
- 脚本会跟踪模式切换，两种都能正确解析

### 打印时间

- 优先读切片软件写的时间注释（它考虑了加速度与 Jerk，更准）
- 无注释时按 `时间 = 距离 / F值 × 60` 逐段累加
- ⚠️ 自算值**未考虑加速度限制**，通常比实际偏快，报告中会标注时间来源

## 正确性校验

`make_sample_gcode.py` 生成的是**已知答案**的样例，用于验证换算逻辑没有写错：

| 指标 | 预期 | 实测 | 结果 |
|---|---|---|---|
| 层数 | 12 | 12 | ✅ |
| 总挤出长度 | 12 × 100 = 1200 mm | 1.2 m = 1200 mm | ✅ |
| 喷嘴温度 | 210 °C | 210 °C | ✅ |
| 热床温度 | 60 °C | 60 °C | ✅ |
| 耗材重量（手算） | 1200 × 2.405 / 1000 × 1.24 = 3.58 g | 3.58 g | ✅ |

**校验的意义**：工具算出来的数如果不是手算能复现的，那它在车间里就不可信。

## 技术边界与取舍

当前实现主动界定了处理范围，以下为**已被识别并明确取舍**的部分：

**当前精确覆盖**
- 移动指令：`G0` / `G1`（直线插补），覆盖主流切片软件输出的绝大多数路径
- 挤出模式：`M82` 绝对 / `M83` 相对，含模式切换跟踪

**待支持的场景（均已评估实现路径）**
- `G2` / `G3` 圆弧插补：部分切片器会输出圆弧，实现方式为将圆弧离散为小线段后做长度累加
- 加速度建模：读取 `M204` 加速度值，以梯形速度曲线替代匀速假设，使自算时间逼近实际值

**口径说明**
- 自算时间未计入加速度与 Jerk，报告中会标注时间来源（切片器注释优先）
- 逐层挤出量统计**正挤出**；回抽（负 E）不计入逐层，但体现在总挤出量中
