# G 代码分析工具 · Slicing Lab

> 把 `.gcode` 当数据分析，而不是当文件打印。
> 输入切片产物，输出**可直接用于报价与工艺决策**的耗材、时间与成本数字。

Python · 核心零第三方依赖 · 已在真实生产文件（38 万行 / 767 层）上验证

---

## 这个工具解决什么问题

切片软件会告诉你"这个模型要打 3 小时、用 30 克料"，但**不告诉你这个数字怎么来的**，也没法批量对比不同参数方案的代价。

在工艺岗上，这带来两个具体麻烦：

| 场景 | 没有工具时 | 有工具时 |
|---|---|---|
| **客户询价** | 凭经验拍一个价，报高了丢单、报低了亏 | 耗材 + 机器工时 + 人工逐项核算，报价有依据 |
| **参数调优** | 换一组参数打一遍，靠感觉说"好像快了点" | 量化对比耗时、耗材、路径有效率，改进可复现 |
| **工艺归档** | 参数散落在各个切片工程文件里 | 逐层数据导出 Excel，形成可追溯的参数对照表 |

工具把"成本"和"时间"从**经验判断**变成**可计算的数字**。

```bash
# 不需要打印机，先生成一个已知答案的样例
```

## 功能

| 指标 | 说明 |
|---|---|
| 挤出路径 / 空驶路径 | 分别统计，并给出**路径有效率**（挤出路径占比，衡量切片参数是否浪费行程） |
| 耗材消耗 | 从 E 轴累计量换算为长度 (m) 与质量 (g) |
| 打印时间 | 优先读切片软件注释（含加速度计算，更准）；无注释则按 F 值自算 |
| 成本核算 | 耗材 + 机器工时 + 人工，所有单价假设均可自定义 |
| 逐层统计 | 每层的 Z 高度、耗时、挤出量，可导出 CSV / Excel（带原生图表） |
| 温度与风扇 | 喷嘴/热床温度设定范围及变更次数、风扇 PWM |
| 元数据识别 | 自动读取机型、材料类型、层高、喷嘴直径 |

## 用你自己的模型

```bash
# 单个文件，指定材料与成本假设
python gcode_analyzer.py my_part.gcode --material PETG --price 80 --machine-rate 3 --labor 2

# 整个文件夹批量分析
python gcode_analyzer.py ./gcode/ --json batch.json

# 对比两种参数方案（这是最有价值的用法）
python gcode_analyzer.py 方案A_0.2mm.gcode --json a.json --quiet
python gcode_analyzer.py 方案B_0.3mm.gcode --json b.json --quiet
# 两个 json 直接对比耗时 / 耗材 / 成本差异
```

### 参数说明

| 参数 | 默认值 | 说明 |
|---|---|---|
| `--material` | PLA | 从内置密度表查密度（PLA / PETG / ABS / ASA / TPU / NYLON / PC） |
| `--density` | — | 直接指定密度 g/cm³，覆盖 `--material` |
| `--diameter` | 1.75 | 耗材直径 mm |
| `--price` | 60 | 耗材单价 元/kg |
| `--machine-rate` | 2.0 | 机器工时费 元/小时（电费 + 设备折旧，按自己情况估） |
| `--labor` | 0 | 人工/后处理成本 元（拆支撑、打磨等） |
| `--json` / `--csv` / `--figure` | — | 导出完整报告 / 逐层数据 / 图表 |

## 计算原理

### 耗材重量

```
截面积 = π × (d/2)²          # d = 1.75 mm，得 2.405 mm²
体积   = 挤出长度 × 截面积    # mm³
质量   = 体积 / 1000 × 密度   # g，因为 1 cm³ = 1000 mm³
```

> **关键点**：G 代码里的 E 值是耗材**长度**，不是体积，也不是重量。
> 换算必须经过截面积这一步 —— 手算与脚本必须一致，否则说明系数写错了。

### 挤出量累计

- `M82` 绝对模式：E 值是累计总量，需用**相邻差值**
- `M83` 相对模式：E 值就是本段挤出量，直接用
- 脚本会跟踪模式切换，两种都能正确解析

### 打印时间

- 优先读切片软件写的时间注释（它考虑了加速度与 Jerk，更准）
- 无注释时按 `时间 = 距离 / F值 × 60` 逐段累加
- ⚠️ 自算值**未考虑加速度限制**，通常比实际偏快，报告中会标注时间来源

## 正确性校验

验证分两层：先用**已知答案**的样例证明换算逻辑没写错，再用**真实生产文件**证明它在实际切片产物上跑得通。

### 第一层：构造样例（已知答案）

`make_sample_gcode.py` 生成一个参数完全可控的样例，预期值可以手算：

| 指标 | 预期 | 实测 | 结果 |
|---|---|---|---|
| 层数 | 12 | 12 | ✅ |
| 总挤出长度 | 12 × 100 = 1200 mm | 1.2 m = 1200 mm | ✅ |
| 喷嘴温度 | 210 °C | 210 °C | ✅ |
| 热床温度 | 60 °C | 60 °C | ✅ |
| 耗材重量（手算） | 1200 × 2.405 / 1000 × 1.24 = 3.58 g | 3.58 g | ✅ |

### 第二层：真实切片文件（交叉核对）

拿真实文件跑时，工具识别的层数必须与切片软件自报的层数一致。

**这一步抓出过一个真 bug。** 这份文件里 `;LAYER_CHANGE` 标记实际出现 767 次，
但工具一开始报 **768** 层。排查发现最后一处"层变化"其实来自文件尾部的配置区：

```
; layer_change_gcode =
```

这是切片软件写在文件末尾的参数赋值，带有 `layer_change` 字样，被"子串匹配"
当成了第 768 次层变化，凭空多出一层。修法是把正则改成不区分大小写、但要求
`LAYER_CHANGE` 之后不能再跟字母数字（`(?![A-Za-z0-9_])`），这样
`;LAYER_CHANGE` 和 `;BEFORE_LAYER_CHANGE` 都能匹配，而 `layer_change_gcode`
被正确排除。

另外还有一处层高标注错误，而且**修错过一次，值得记下来**：一开始工具把第一层标成
**0.6mm**，看着像是"取到了真实的打印高度"，其实是错的——0.6mm 是探针/调平那一段的
**抬 Z 高度**，不是成型高度。这份文件的第一层实际打印在 **0.2mm**。

原因是这类机型在层变化之后还有一段走位，第一条带 Z 的指令写的是安全高度；
而切片软件其实已经把答案直接写在文件里了：

```
;LAYER_CHANGE
;:0.2
;HEIGHT:0.2      ← 这个才是本层高度
```

最终的取值优先级因此改成：**切片软件的 `;HEIGHT:` 标注 → 第一条"边挤边走"指令的 Z
→ 本层第一条带 Z 的指令**。修完第一层正确标为 0.2mm。这也说明"看起来更合理的启发式"
不等于正确——**优先相信文件里已经写明的元数据**，比从坐标反推更稳。

| 检查项 | 修复前 | 修复后 |
|---|---|---|
| 识别层数 | 768 ❌ | **767** ✅ |
| 第一层层高标注 | 0.6 mm ❌（读到探针抬 Z） | **0.2 mm** ✅（读 `;HEIGHT:` 标注） |
| 样例文件回归 | 12 层 | 12 层（未受影响）✅ |

> 顺带一个真实细节：这份文件的表头写 `层高 0.2mm`，但实际用的是**变层高**——
> 逐层 `;HEIGHT:` 值在 0.2 / 0.3 / 0.4mm 之间变化（1301 处标注）。所以逐层表里的
> Z 列**本来就不该单调递增**，这是切片策略本身的结果，不是解析错误。

> 这类问题**只在真实文件上才会暴露**：构造样例太规整，既没有尾部配置区，
> 也没有切片软件那套层标记约定。

**校验的意义**：工具算出来的数如果不是手算能复现的、层数不是能和切片软件对上的，那它在车间里就不可信。

## 技术边界与取舍

当前实现主动界定了处理范围，以下为**已被识别并明确取舍**的部分：

**当前精确覆盖**
- 移动指令：`G0` / `G1`（直线插补）
- 挤出模式：`M82` 绝对 / `M83` 相对，含模式切换跟踪

**已知偏差（会在报告里低估，使用时需留意）**
- **圆弧插补 `G2` / `G3` 当前未计入**。部分切片器会对圆角、孔洞输出圆弧指令，
  而本工具只累加 `G0`/`G1`。实测某真实文件：`G2` 38,386 条 + `G3` 39,035 条，
  圆弧挤出量 4,489 mm，占全部挤出量的 **9.8%**——也就是说该文件的耗材长度、
  重量与材料成本会被低估约一成。实现方式为读取 `I`/`J` 圆心偏移后离散为小线段，
  已列入后续规划。

**下一步计划**
- `G2` / `G3` 圆弧支持：读取 `I`/`J` 圆心偏移，离散为小线段后累加（收益见上）
- 加速度建模：读取 `M204` 加速度值，以梯形速度曲线替代匀速假设，使自算时间逼近实际值

**口径说明**
- 自算时间未计入加速度与 Jerk，报告中会标注时间来源（切片器注释优先）
- 逐层挤出量统计**正挤出**；回抽（负 E）不计入逐层，但体现在总挤出量中
- 逐层挤出量之和小于总挤出量是正常现象（各层统计不含层间的回抽与空驶）
